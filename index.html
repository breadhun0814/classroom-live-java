기술 설계

서버는 수업 공간을,
브라우저는 화면을 연결합니다.

계정과 대화는 교실 PC에 보관하고, 영상은 공유자와 시청자 사이로 직접 전달합니다. 실행 중 외부 클라우드 서비스에 의존하지 않는 구성을 선택했습니다.

데이터가 오가는 방식

두 가지 경로를
나누어 설계했습니다.

계정·방·채팅과 SDP·ICE 연결 정보는 Java HTTPS 서버를 거칩니다. 브라우저는 응답 처리 후 약 1.8초마다 새 상태를 조회합니다.

서버 한 대의 실행 단위

JDK의 HTTPS 서버가 API와 웹 UI를 함께 제공합니다. 인증서 도구와 정적 자원을 포함한 배포 흐름을 구성했습니다.

Java 17+HttpsServerkeytool

브라우저의 화면과 대화

화면 캡처와 P2P 연결, 화질 설정과 연결 진단을 제공합니다. 학생 PC에는 Java를 설치하지 않아도 됩니다.

Vanilla JSWebRTCHTML / CSS

데이터와 운영 도구

계정·방·대화는 로컬 JSON에 저장합니다. Swing 관리 앱에서 서버를 시작·종료하고 HTTPS 상태를 확인합니다.

JSONSwingPowerShell

구현에서 다룬 문제

화면 공유를 다시 시작할 때, 이전 신호가 남는다면?

현재 방의 수명과 화면 공유 회차, 개별 연결을 generation·epoch·connectionId로 구분합니다. 늦게 도착한 이전 응답을 걸러내고, 원격 설명보다 먼저 도착한 ICE 후보는 대기열에 보관한 뒤 적용합니다.

학생 설치팩에 서버의 개인 자료가 포함되지 않도록

공개 CA 인증서와 접속 안내를 학생 설치팩에 담고, 서버 인증서의 개인 키와 회원 데이터는 서버에 보관합니다. 자동 테스트에서 생성된 설치팩의 내용을 확인합니다.

서버를 중복으로 실행하거나 관리 창을 닫는다면?

데이터 폴더의 파일 잠금으로 중복 서버를 제한합니다. 관리 앱은 자식 서버에 전용 입력 파이프로 종료 요청을 보내며, 부모 파이프가 닫히는 경우에도 관리 모드 서버가 종료되도록 구성했습니다.
