방을 바로 찾기

방을 검색하거나 내가 만든 방만 볼 수 있습니다. 방장은 기존 참여자를 내보내지 않고 새 입장만 잠글 수 있습니다. 최근 들어간 방은 이 브라우저에만 표시되며 비밀번호는 저장하지 않습니다.

입장 전에 소리 확인

마이크 입력 막대와 스피커 테스트로 소리를 확인합니다. 연결 도움말에서 화면과 통화 상태를 확인하고, 통화를 끊지 않고 손을 들어 발언 의사를 표시할 수 있습니다.

공유 화면을 작은 창으로

지원되는 브라우저에서 공유 화면을 별도 창에 띄우고 채팅이나 화상 통화를 이어갑니다. 재연결해도 참여자별 음소거가 유지됩니다. 연결이 느리면 720p·15fps 프리셋을 선택하거나 공유 중에 바로 부하를 줄일 수 있습니다. 시작 전에 선택한 공유 설정은 이 브라우저에서 다시 열어도 유지됩니다.

방의 대화 가져가기

메시지에 답장하고, 방장은 공지나 참고 메시지를 대화 위에 고정할 수 있습니다. 전송 키는 Enter 또는 Ctrl+Enter로 설정합니다. 보관된 대화는 이름이나 내용으로 검색하고, 일반 메시지와 코드만 따로 찾아볼 수 있습니다. 자동 복사가 차단되면 선택된 메시지를 직접 복사할 수 있고, 보관된 대화 전체는 TXT로 저장할 수 있습니다. 좁은 화면에서는 상단 버튼으로 화면·통화·대화로 이동하고, 글자 크기와 전송 키는 대화 설정에서 바꿉니다.

계정과 대화는 서버 PC에 보관합니다. 공유 화면은 발표자에서 시청자에게, 통화 영상과 음성은 통화 참여자끼리 WebRTC로 직접 전달합니다. 두 연결은 독립적으로 시작하고 종료할 수 있습니다.

공유한 화면은 어떻게 보이나요?

  1. 캡처

    발표자가 공유할 탭, 창, 전체 화면을 선택합니다. 브라우저의 getDisplayMedia()가 선택한 화면을 영상 트랙으로 만듭니다.

  2. 연결

    발표자와 시청자가 연결 정보인 SDP와 ICE를 HTTPS 서버를 통해 교환합니다. 브라우저는 이 정보로 WebRTC 연결을 설정합니다.

  3. 재생

    영상 트랙은 발표자 브라우저에서 각 시청자 브라우저로 직접 전송됩니다. 받은 화면은 방 상단의 영상 영역에서 재생하고, 카메라 타일은 그 아래에 표시합니다.

화상 통화는 별도의 연결을 사용합니다. 사용자가 켠 카메라와 마이크는 getUserMedia()로 가져옵니다. 통화에 참여한 브라우저끼리 영상과 음성을 교환하므로, 통화에서 나가거나 재연결해도 화면 공유를 계속 볼 수 있습니다.

구현에서 다룬 문제

화면 공유를 다시 시작할 때, 이전 신호가 남는다면?

현재 방의 수명과 화면 공유 회차, 개별 연결을 generation·epoch·connectionId로 구분합니다. 늦게 도착한 이전 응답을 걸러내고, 원격 설명보다 먼저 도착한 ICE 후보는 대기열에 보관한 뒤 적용합니다.

참여자 설치팩에 서버의 개인 자료가 포함되지 않도록

공개 CA 인증서와 접속 안내를 참여자 설치팩에 담고, 서버 인증서의 개인 키와 회원 데이터는 서버에 보관합니다. 자동 테스트에서 생성된 설치팩의 내용을 확인합니다.

서버를 중복으로 실행하거나 관리 창을 닫는다면?

데이터 폴더의 파일 잠금으로 중복 서버를 제한합니다. 관리 앱은 자식 서버에 전용 입력 파이프로 종료 요청을 보내며, 부모 파이프가 닫히는 경우에도 관리 모드 서버가 종료되도록 구성했습니다.

회의·발표·스터디에서 사용하기

화면 공유와 화상 통화를 함께 쓰는 법

같은 로컬 네트워크에서 Chrome 또는 Edge로 초대 링크를 엽니다. 로그인하면 초대 코드가 채워지므로 운영자에게 별도로 받은 방 비밀번호를 입력하면 됩니다.

  1. 발표자 화면 공유

    화면 공유 시작을 누르고 브라우저에서 공유할 탭이나 창을 선택합니다. 한 번에 한 명이 공유할 수 있습니다. 지원되는 브라우저에서는 화면을 작은 창으로 보기로 공유 화면을 띄워 두고 채팅이나 통화를 계속할 수 있습니다.

  2. 참여자 화상 통화

    통화 입장 설정에서 카메라를 미리 보고, 마이크 입력 막대와 스피커 테스트로 소리를 확인합니다. 기기가 없거나 권한을 줄 수 없다면 듣기만 참여를 선택하세요. 원하면 기기 선택을 이 브라우저에만 기억하도록 설정할 수 있습니다.

  3. 공유와 통화를 따로 조작

    통화에서 나가도 공유 화면은 유지됩니다. 발표자가 공유를 중지해도 통화는 계속됩니다. 통화 연결이 끊기면 통화 다시 연결을 사용하세요.

처음 연결할 때 두 대의 PC로 확인하기

  1. 같은 로컬 네트워크에서 서버 주소를 열고, 두 사람 모두 같은 방에 입장합니다.
  2. 한 사람이 화면 공유 시작을 눌러 탭이나 창을 고릅니다. 다른 사람의 화면에 공유 내용이 보이면 영상 연결이 된 상태입니다.
  3. 두 사람 모두 통화에 참여해 한 사람은 마이크를 켜고, 다른 사람은 들리는지 확인합니다. 입장 전 스피커 테스트로 소리 출력도 먼저 확인할 수 있습니다.
  4. 한 기능만 문제가 있다면 화면 공유·통화 연결 도움말을 열어 해당 기능의 상태와 재연결 버튼을 확인합니다. 운영자에게 도움을 요청할 때는 연결 진단 복사를 사용하세요.

실제 사용 환경에서 더 확인할 것

여러 PC의 영상 품질, 8대 PC 동시 영상, 장시간 사용은 이번 검증에 포함하지 않았습니다. 실제 화면 선택 창, 서로 다른 PC와 기기 조합, 여러 명이 동시에 통화할 때의 품질은 현장에서 확인해야 합니다. 사용 중인 네트워크의 PC 간 통신 정책과 PC 성능에 따라 연결·화질이 달라집니다.

이 사이트의 예시 체험은 서버 로그인이나 실제 영상 전송을 수행하지 않습니다.

보안과 개인정보 보호

로컬 서버는 HTTPS와 허용된 사설 네트워크 대역을 사용합니다. 로그인 세션은 보안 쿠키로 관리하며, 미디어 연결 정보를 요청할 때 방 참여 권한을 확인합니다.

  • 허용된 네트워크로 제한

    방화벽과 서버 허용 대역을 사용하는 내부망으로 좁히고 공유기 포트 포워딩은 피하세요. PC 간 통신이 막힌 환경은 네트워크 담당자와 확인하세요.

  • 서버 자료 보호

    참여자에게는 생성된 참여자 설치팩만 전달하세요. 서버의 CA 개인 키, 계정·채팅이 들어 있는 데이터 폴더와 백업에는 관리자만 접근하게 하세요.

  • 계정과 화면 관리

    계정 준비가 끝나면 관리자 화면에서 신규 회원가입을 닫으세요. 기존 계정은 그대로 로그인할 수 있습니다. 관리자 조작 기록에서 가입 변경이나 이용 정지·퇴장 조치를 확인할 수 있습니다. 공유할 자료가 열린 탭이나 창을 공유하고, 개인정보가 보이는 알림이나 문서는 미리 닫으세요.

서버는 영상과 음성을 녹화하지 않습니다. 참여자가 운영체제나 별도 도구로 화면을 기록할 수는 있습니다.

추가 개발 시에는 관리자 세션 유휴 만료, 계정·방·권한 변경 감사 기록의 보관 기간, 방별 채팅 삭제 정책을 먼저 정하는 것이 좋습니다.
