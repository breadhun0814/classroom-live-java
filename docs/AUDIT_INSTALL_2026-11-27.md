# 사이트 전체 점검·설치 편의 개선 · 2026-11-27

## 사이트 디자인·체험 점검

공개 포트폴리오에 직접 접속해 기능 탭, 대화 입력, 코드 복사, 예시 회원 이용 상태 변경, 기술 경로 설명, 펼침 문답, 모바일 메뉴와 설치 동선을 확인했습니다.

확인해 수정한 내용:

- **불완전한 초기화:** 화질 프리셋이 남고, 25개 메시지 한도 때문에 지워진 최초 예시 대화가 복원되지 않았습니다. 초기 메시지 복제본·방 입력·프리셋·관리 상태를 함께 복구하도록 수정했습니다.
- **복사 권한 거부:** 버튼 문구만 바뀌던 경로를 실제 코드 선택과 복사 안내로 바꿨습니다.
- **모바일·입력:** 불필요한 강제 줄바꿈을 줄이고, 모바일 메뉴가 큰 화면으로 전환될 때 닫히게 했습니다. 이미지 확대 중 배경 스크롤을 잠그고, 한글 조합 중 Enter로 전송되지 않도록 처리했습니다.
- **체험 보강:** 예시 코드·비밀번호의 오류/성공을 확인하는 방 입장 흐름과 다음 코드 채팅으로 이동하는 버튼을 추가했습니다. 모두 브라우저 안에서만 동작합니다.
- **설치 안내:** 기존 수동 안내로 바로 이동하던 동선을 밝은 디자인의 서버·학생별 `install.html`로 바꾸고 Windows 실행용 ZIP을 연결했습니다. 5개 언어 상세 안내는 보존했습니다.

실제 브라우저에서 수정한 로컬 사이트의 방 입장, 전송, 초기화, 프리셋, 확대·닫기, 경로 설명, 문답, 390px 모바일 메뉴와 설치 화면을 조작했습니다. 실행용 ZIP도 페이지의 실제 버튼으로 내려받았습니다. 기본 PC 화면과 390px 화면에서 가로 넘침이 없고, 확대 시 배경 스크롤이 잠기는 것을 확인했습니다.

`tests/portfolio.test.cjs`는 메시지 한도 이후 초기화, 방 오류/성공, 클립보드 거부 대체 경로, 한글 조합, HTML 텍스트 표시, 설치 링크·ZIP 자원을 확인합니다. 기존 5개 언어 가이드 테스트도 통과했습니다.

## 프로그램 설치 편의 개선

### 빠른 시작

`Start-Classroom.cmd` 한 곳에서 다음 흐름을 진행합니다.

1. `java-path.txt`, 폴더의 `.runtime/java`, JAVA_HOME, PATH와 일반 JDK 설치 폴더·레지스트리에서 Java 17+ JDK를 찾습니다. `javaw`·`keytool`과 필요한 모듈을 확인합니다.
2. Java가 없고 사용자가 다운로드를 선택하면 공식 Eclipse Temurin 21 ZIP을 받습니다. API의 SHA-256과 파일 해시를 비교한 뒤, ZIP 경로를 검사하고 프로그램 폴더에 준비합니다. 시스템 Java 설정은 변경하지 않습니다.
3. 최초 실행이면 교실 주소·대역·포트·관리자 계정을 설정합니다. 감지한 IPv4와 실제 prefix 기반 CIDR은 사용자가 확인할 기본값으로만 제안합니다. 기존 서버 설정이 있으면 재설정하지 않습니다.
4. 필요 시 사용자가 방화벽 설정 요청을 선택하고 Windows UAC를 직접 승인합니다. 교실의 설정한 TCP 포트·대역에 한정하며, 승인하지 않은 경우 완료되지 않았음을 안내합니다.
5. 전용 아이콘의 바탕화면 앱 바로가기를 만들고 관리 앱과 서버를 자동으로 시작합니다. 바로가기는 CMD나 PowerShell 없이 javaw를 직접 실행합니다. 학생용 인증서 등록은 기존 설치팩의 사용자 확인 절차를 유지합니다.

공유 Java 검색 코드는 기존 콘솔 실행·관리 앱 실행·바로가기 생성에도 적용했습니다. Windows PowerShell 5.1이 한국어 스크립트를 정확히 읽도록 관련 `.ps1`을 UTF-8 BOM으로 저장했습니다.

공식 배포 정보: [Adoptium API 사용 안내](https://adoptium.net/installation/ci-scripts/), [공식 Temurin 배포](https://adoptium.net/temurin/releases/?version=21).

### 실행용 패키지

`node scripts/package-windows.cjs`로 `downloads/ClassroomLive-Windows.zip`을 만듭니다. 서버·관리 앱 JAR, 빠른 시작, 운영 스크립트와 안내 등 29개 실행 파일을 포함합니다. 소스·테스트·node_modules·실제 data·개인 키·다운로드한 JDK는 포함하지 않습니다. 학생은 서버용 패키지 대신 교실 서버가 생성한 `STUDENT_SETUP.zip`을 사용합니다.

### 확인 결과

Windows PowerShell 5.1에서 격리된 한글·공백 경로에 실행용 ZIP을 풀어 테스트했습니다.

- **설치 검증 40개 항목 통과:** 스크립트 문법, Java 검색·구버전/도구 누락·잘못된 고정 경로, CIDR 계산, ZIP 경로 이탈 차단, SHA-256 불일치 차단, 첫 설정, read-only 확인 모드, 재실행·기존 데이터 바이트 보존, 실제 `.lnk` 생성과 경로, 한글 경로에서의 실제 CMD 진입점, 패키지의 29개 파일과 원본의 일치를 검사했습니다.
- **공식 JDK 다운로드 경로 통과:** 실제 Eclipse Temurin 21을 내려받아 해시 확인·압축 해제·실행하고, 이 폴더 전용 Java로 새로운 서버 설정과 학생 설치팩 생성을 완료했습니다. 설치 테스트는 PATH/JAVA_HOME을 바꾸지 않았습니다.
- 새 서버 JAR를 빌드한 뒤 기존 `ServerTests`, `ManagedServerTests`, 실제 HTTPS 백엔드와 연결하는 `ui.test.cjs`가 통과했습니다. 프로세스 관리 테스트는 기존과 같이 자식 출력까지 UTF-8로 지정했습니다.

### CMD 없는 바탕화면 서버 앱

바로가기는 전용 ICO를 사용하며 `javaw.exe`에서 관리 앱의 `--start` 경로를 직접 실행합니다. 콘솔 창 없이 서버가 자동 시작되고 관리 창에서 상태 확인·종료·재시작을 할 수 있습니다. Java 관리 앱에는 같은 로고의 창 아이콘도 적용했습니다.

바로가기의 실제 대상·인수·아이콘 경로를 검사했습니다. `ManagedServerTests`는 운영 시와 같은 Swing 시작 경로를 테스트에서 창만 숨겨 호출하고, 서버가 자동 시작되어 신뢰된 HTTPS로 응답하고 정상 종료되는 것을 확인합니다. 기존 데이터 바이트 보존도 계속 검사합니다.

실행 명령:

```powershell
java Build.java test
node scripts/package-windows.cjs
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tests/InstallTests.ps1 -DownloadJava
node tests/portfolio.test.cjs
node tests/guides.test.cjs
```

### 검증의 범위

설치 테스트는 같은 Windows PC의 격리된 폴더에서 수행했습니다. 실제 시스템 방화벽 변경·UAC 승인·CA 신뢰 저장소 등록은 하지 않았습니다. 실제 바탕화면 아이콘을 사람이 더블 클릭해 조작하는 전 과정, 별도 물리 PC의 학생 설치, Windows ARM64는 이번 검증에 포함하지 않았습니다. 여러 PC의 실제 영상 품질·장시간 수업도 여전히 현장 확인이 필요합니다.
