# Classroom Live — Windows 서버 관리 앱 추가팩

이미 잘 작동하는 Java 서버에 그래픽 실행 창을 추가합니다.
학생 PC는 수정하지 않습니다. 주소·인증서·계정·방·채팅은 유지합니다.

## 1. 서버 PC에서 한 번만 적용

1. 수업이 끝난 뒤 기존 서버 터미널에서 Ctrl+C로 서버를 종료하세요.
2. 기존 서버 폴더 전체를 다른 위치에 복사해 백업하세요. 이 백업에는 비공개 인증서가 있으므로 학생에게 보내지 마세요.
3. 받은 classroom-live-server-app.zip을 새 폴더에 압축 해제하세요. 압축 안에서 바로 실행하지 마세요.
4. 압축 안의 파일·폴더를 모두 기존 ClassroomLive.jar가 있는 폴더에 복사하세요. 같은 이름의 파일은 덮어씁니다. scripts/src/tests는 기존 폴더와 병합하세요.
5. 기존 data 폴더와 java-path.txt는 그대로 둡니다. 추가팩에는 개인 데이터·인증서가 들어 있지 않습니다.
6. 기존 서버 폴더의 Server-App.cmd를 더블 클릭합니다.
7. 앱 창에서 '서버 시작'을 누릅니다.
8. '실행 중 · HTTPS 응답 정상'이 표시되면 '사이트 열기'를 누릅니다.
9. 학생들은 기존 주소로 접속하면 됩니다. 예: https://192.168.22.50:8443/

01-Setup.cmd를 다시 실행하거나 인증서를 새로 만들 필요가 없습니다.
재시작 후에는 학생들도 다시 로그인하고 방에 입장해야 합니다. 화면 공유도 다시 시작합니다.

## 2. 매일 사용

- 서버 켜기: Server-App.cmd → 서버 시작.
- 주소 전달: 주소 복사. 실제 주소는 기존 data/server.json에서 자동으로 읽습니다.
- 수업 시작: 사이트 열기 → 기존 관리자 계정으로 로그인 → 방 입장 → 화면 공유.
- 창을 최소화하면 서버는 계속 실행됩니다.
- 서버 끄기: 서버 종료 → 확인. 연결은 끊기고 저장된 데이터는 유지됩니다.
- 창의 X: 서버 실행 중이면 종료 확인창이 뜹니다. '아니요'를 누르면 계속 실행됩니다.
- 서버 PC 전원·절전 상태는 직접 관리하세요. 절전이나 종료 중에는 접속할 수 없습니다.
- 편하게 실행하려면 Server-App.cmd를 우클릭 → 추가 옵션 표시 → 보내기 → 바탕 화면에 바로 가기 만들기.

학생 PC에는 이 추가팩을 설치하지 않습니다. 학생의 Java/Eclipse/Python 설치도 필요 없습니다.
학생 주소나 서버 IP·포트를 바꾸지 마세요. 현재 연결이 잘 된다면 방화벽과 인증서도 그대로 유지하세요.
서버 앱은 기존 Java 17 이상의 java-path.txt / JAVA_HOME / PATH 설정을 사용합니다.
추가 유료 서비스나 Supabase는 사용하지 않습니다. 기존 컴퓨터·네트워크·전기 비용은 별도입니다.

## 3. 문제가 생겼을 때

- 기존 02-Start.cmd 창에서 서버가 켜져 있음: 그 창에서 Ctrl+C로 종료하고 앱에서 시작하세요. 앱은 다른 창에서 켠 서버를 강제로 끄지 않습니다.
- 중복 실행: 실행 기록에 기존 서버가 실행 중이라는 안내가 나옵니다. 서버 앱을 하나만 사용하세요.
- 설정 파일 없음: 새로 압축 해제한 폴더가 아니라 기존 data와 ClassroomLive.jar가 있는 폴더로 파일을 복사했는지 확인하세요.
- Java 경로 오류: 기존 java-path.txt를 유지하세요. 00-Java-Check.cmd가 정상인 Java 17 이상 설치의 bin/javaw.exe도 필요합니다.
- 시작 중 / 응답 확인 중: 아래 실행 기록을 확인하세요. 포트 충돌·인증서·설정 오류를 먼저 해결해야 합니다. 앱의 정상 상태는 서버 PC 내부의 HTTPS 응답 확인이며, 모든 학생의 영상 연결까지 보증하지는 않습니다.
- 앱에서 사이트를 열었는데 인증서 경고: 이 Windows 사용자에게 기존 교실 인증서가 등록되어 있는지 확인하세요. 앱 내부 확인은 기존 CA만 신뢰하며 브라우저의 인증서 등록을 대신하지 않습니다.
- Windows가 다운로드 파일을 차단: 교수님이 제공한 원본인지 확인한 뒤 학교 정책에 따라 허용하세요. 보안 프로그램이나 방화벽 전체를 끄지 마세요.
- 종료 중에는 프로세스가 안전하게 마칠 때까지 기다리세요. 정상 종료는 저장된 계정·방·채팅을 삭제하지 않습니다.

문제 해결을 요청할 때는 앱 실행 기록을 보내세요. 비밀번호·data 폴더·개인 인증서 키는 보내지 마세요.
이전 방식이 편하면 앱을 닫고 기존 02-Start.cmd로 실행할 수 있습니다.
업데이트를 되돌리려면 서버를 끈 뒤 백업한 이전 ClassroomLive.jar로 복원하세요. data는 유지하세요.

## 4. 포함 파일 및 개발자 설명

- Server-App.cmd: Windows 실행 진입점.
- scripts/control.ps1: 기존 Java 경로를 찾아 javaw로 관리 창을 엽니다.
- ServerControl.jar: 그래픽 서버 관리 창. 같은 폴더의 ClassroomLive.jar가 필요합니다.
- ClassroomLive.jar: 기존 웹 UI·API에 로컬 자식 프로세스 종료 모드만 추가했습니다.
- src/ServerControl.java, src/ManagedServer.java, src/ClassroomServer.java: 전체 변경 소스.
- Build.java: Java 17 이상에서 java Build.java test로 빌드.
- tests/ManagedServerTests.java: 실제 JAR 시작·종료·재시작·중복 차단·연결 파이프 종료·기존 파일 보존 검사.

앱은 자식 서버와 비공개 표준입력 파이프로 통신합니다. 원격 종료 API를 만들지 않습니다.
정상 종료 요청 시 HTTPS 요청 처리를 끝내고 포트와 데이터 잠금을 해제합니다.
앱이 비정상 종료되어 파이프가 닫히면 서버도 종료하도록 했습니다. Windows 강제 전원 차단 시의 데이터 무결성까지 보장하는 기능은 아닙니다.
기존 HTTP 경로·데이터 형식·화면 공유 방식·CA·학생 설치팩 형식은 바꾸지 않았습니다.

검증: Linux의 Java 17에서 실제 JAR/HTTPS로 시작·종료·재시작·중복 실행 차단·기존 파일 보존 및 기존 백엔드 회귀 테스트를 실행합니다.
Windows의 실제 더블 클릭 실행과 그래픽 창은 이 환경에서 직접 확인하지 못했습니다. 적용 전 서버 폴더 백업을 유지하세요.
