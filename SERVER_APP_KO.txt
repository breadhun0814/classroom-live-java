# Classroom Live — 바탕화면 서버 관리 앱

서버 PC에만 적용하는 추가팩입니다. 학생 PC·기존 주소·회원·방·채팅·인증서는 유지합니다.
바탕화면 바로가기는 javaw.exe로 서버 관리 창을 직접 엽니다. CMD 창을 수업 내내 켜둘 필요가 없습니다.

## 1. 기존 서버에 적용

1. 기존 서버를 종료하세요. 기존 관리 앱 또는 02-Start.cmd 창에서 종료합니다.
2. 기존 서버 폴더 전체를 복사해 비공개 백업을 만드세요.
3. 받은 classroom-live-server-app.zip을 새 폴더에 압축 해제하세요.
4. 압축 안의 내용물을 기존 ClassroomLive.jar와 data 폴더가 있는 서버 폴더로 복사하세요. 같은 파일은 덮어씁니다. scripts/src/tests는 기존 폴더와 병합합니다.
5. 기존 data 폴더와 java-path.txt는 그대로 유지하세요. 추가팩에는 개인 데이터·인증서가 없습니다.
6. 기존 서버 폴더에서 Create-Desktop-Shortcut.cmd를 한 번 실행하세요. 관리자 권한은 필요 없습니다.
7. 바탕화면에 'Classroom Live 서버' 바로가기가 생깁니다.
8. 이제부터 바탕화면 바로가기를 더블 클릭하면 검은 CMD 창 없이 서버 관리 앱만 열립니다.
9. 앱에서 '서버 시작'을 누르고 HTTPS 응답 정상 표시를 확인하세요.

이전 버전으로 실행 중인 앱을 먼저 종료한 후 적용하세요. 덮어쓰더라도 이미 실행 중인 프로세스는 새 버전으로 바뀌지 않습니다.
원본 서버 폴더는 이동하거나 삭제하지 마세요. 실행 파일 하나를 바탕화면으로 옮기는 대신 바로가기를 사용합니다.
서버 폴더나 Java 설치 경로를 옮겼다면 새 위치에서 Create-Desktop-Shortcut.cmd를 다시 실행하세요.
현재 정상 작동 중인 서버에는 01-Setup.cmd를 다시 실행하지 않습니다. data/server.json이 없다면 기존 서버 폴더를 먼저 찾으세요.

## 2. 매일 사용

- 바탕화면 'Classroom Live 서버' 더블 클릭 → 관리 앱 열림.
- '서버 시작' → 교실 서버 실행.
- '서버 종료' → 확인 후 서버 종료. 학생 연결은 끊기고 저장된 데이터는 유지됩니다.
- '사이트 열기' → 기존 HTTPS 주소의 사이트 열기.
- '주소 복사' → 기존 설정의 주소 복사.
- 최소화 → 앱과 서버 계속 실행.
- 앱의 X → 실행 중이면 서버 종료 여부 확인. '아니요'이면 계속 실행.

이번 버전의 바로가기로 실행한 앱은 CMD 창과 독립적으로 동작합니다. 다른 CMD 창을 닫아도 앱과 서버는 종료되지 않습니다.
학교 PC를 종료하거나 절전 상태로 만들면 서비스는 중단됩니다. 서버 PC와 관리 앱은 수업 중 계속 켜두세요.
서버 재시작 후에는 학생들도 다시 로그인·방 입장·화면 공유를 해야 합니다.
학생 PC는 수정하지 않습니다. 기존 주소(예: https://192.168.22.50:8443/)와 인증서를 그대로 사용합니다.
학생에게 Java/Eclipse/Python을 설치할 필요도 없습니다. 서버는 기존 Java 17 이상을 사용합니다.

## 3. 폴더 안에서 실행할 때

Server-App.cmd는 창 없는 실행기로 연결한 뒤 끝납니다. 서버 관리 앱은 계속 실행됩니다.
Server-App.vbs를 더블 클릭해도 검은 창 없이 실행됩니다. 학교에서 VBScript를 제한하면 바탕화면 바로가기를 사용하세요.
바탕화면 바로가기는 VBScript나 CMD를 거치지 않고 Java GUI를 직접 실행합니다.
Java에 .jar 연결이 등록된 PC는 ServerControl.jar 더블 클릭으로도 실행할 수 있습니다.

## 4. 문제가 생겼을 때

- 'data/server.json 없음': 다운로드 폴더가 아닌 기존 data가 있는 서버 폴더에서 바로가기 생성기를 실행하세요. data를 새로 만들거나 삭제하지 마세요.
- 바로가기 실행이 안 됨: 기존 서버 폴더에서 Server-App-Debug.cmd를 실행하세요. 검은 창에 상세 오류가 남습니다. 이 진단 실행에 한해서는 검은 창을 닫으면 앱이 종료될 수 있습니다.
- Java 경로 오류: 기존 java-path.txt를 유지하세요. java.exe와 javaw.exe가 함께 있는 Java 17 이상 데스크톱 JDK가 필요합니다.
- 기존 서버가 실행 중: 02-Start.cmd 창에서 Ctrl+C로 종료한 뒤 관리 앱에서 시작하세요. 앱은 다른 창에서 켠 서버를 강제로 종료하지 않습니다.
- 예전 CMD를 닫으면 같이 꺼짐: 이전 버전으로 켠 앱을 모두 종료하고, 새 파일을 복사한 뒤 새 바탕화면 바로가기로 다시 실행하세요.
- 인증서 경고: 현재 Windows 사용자의 기존 교실 CA 등록 상태를 확인하세요. 기존 data/tls를 지우거나 CA를 재생성하지 마세요.
- 바로가기 이름이 보이지 않음: 생성 성공창을 확인하세요. 생성기는 현재 사용자의 실제 바탕화면 경로(OneDrive 등의 리디렉션 포함)에 바로가기를 만듭니다.
- 학교 정책으로 스크립트/Java 실행이 차단됨: 학교 담당자에게 요청하세요. 보안 프로그램과 방화벽 전체를 끄지 마세요.

시작 확인 기록은 data/logs/server-app-*.log에 남을 수 있습니다. 오류 화면 또는 진단 실행 창을 공유하세요. 비밀번호·전체 data·인증서 개인 키는 보내지 마세요.

## 5. GitHub에 수정본 올리기

1. 저장소의 Add file → Upload files를 누릅니다.
2. 이 추가팩을 압축 해제한 내용물을 올립니다. ZIP 자체나 바깥 폴더를 올리지 않습니다.
3. 기존 파일과 같은 이름·위치인지 확인합니다. scripts 폴더도 포함합니다.
4. Commit changes로 저장합니다.
5. GitHub 업로드와 실제 서버 적용은 별개입니다. 실제 서버에도 1번 절차를 적용해야 합니다.

실제 서버의 data 폴더·개인 인증서·백업·java-path.txt·로그는 올리지 마세요. 원본 서버 전체를 GitHub 업로드 대상으로 선택하지 마세요.

## 6. 포함 파일과 검증

- ClassroomLive.jar: 기존 서버·웹 UI를 포함한 Java 17 서버.
- ServerControl.jar: 시작·종료·접속 버튼이 있는 독립 GUI 앱.
- Create-Desktop-Shortcut.cmd 및 scripts/create-shortcut.ps1: 현재 사용자의 바탕화면에 GUI 직접 실행 바로가기 생성.
- Server-App.cmd / Server-App.vbs / scripts/control.ps1: 폴더에서 창 없이 실행, 시작 전 검사와 실패 안내.
- Server-App-Debug.cmd: 문제 해결용 콘솔 실행.
- src 및 Build.java, tests/ManagedServerTests.java: 변경 소스·빌드·실제 프로세스 테스트.

데이터 형식·접속 주소·CA·웹 UI·학생 설치팩 형식은 유지합니다. 서버의 Windows 자식 프로세스도 javaw.exe로 실행하여 콘솔 창에 의존하지 않습니다.
종료는 부모 앱의 비공개 표준입력 파이프로 요청합니다. 원격 종료 API를 추가하지 않습니다.
앱 자체를 강제 종료하거나 Windows 전원을 갑자기 끄는 경우까지 정상 종료를 보장하지는 않습니다.

Linux Java 17에서 실제 JAR 시작·종료·재시작·중복 차단·파이프 닫힘 시 종료·기존 계정/설정/CA/학생팩 보존·다른 작업 폴더에서 JAR 자기 위치 찾기를 검증했습니다.
Windows의 바로가기 생성·창 없는 실행은 이 환경에서 직접 실행하지 못했습니다. 최초 적용 후 서버 PC에서 확인이 필요합니다.

추가 유료 서비스나 Supabase를 사용하지 않습니다. 기존 컴퓨터·네트워크·전기 비용은 별도입니다.
